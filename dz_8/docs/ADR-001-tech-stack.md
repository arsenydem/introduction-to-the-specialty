# ADR-001: Стек и границы проекта

**Статус:** принято (учебный проект)  
**Дата:** 2026

## Контекст

Нужен прототип Task Manager с демонстрацией CI, Docker, тестов и security-практик в рамках курса.

## Решение

| Область | Выбор | Причина |
|---------|-------|---------|
| API (основной для тестов) | Python 3.12 + FastAPI | Быстрые тесты, TestClient, типизация |
| API (первая версия) | Node.js + Express | Простой старт, знакомый стек |
| Хранение | In-memory | Минимум инфраструктуры для учебных ДЗ |
| Контейнер | Docker multi-stage Alpine | Малый образ, воспроизводимость |
| CI | GitHub Actions | Интеграция с PR, бесплатно для public repo |
| SAST | Semgrep | Не нужен отдельный сервер (в отличие от SonarQube) |
| SBOM / CVE | Syft + Trivy | Стандарт де-факто в DevSecOps |
| E2E | Playwright | Стабильнее Selenium для учебных сценариев |

## Последствия

**Плюсы:** каждое ДЗ изолировано в папке; легко проверять по критериям.  
**Минусы:** дублирование (Node и Python); нет единого production-деплоя.

## Альтернативы (отклонены)

- **SonarQube** — требует сервер; для курса избыточен.
- **Только Node** — хуже покрыть Python-ориентированные примеры Semgrep/pytest в материалах курса.
- **PostgreSQL сразу** — усложняет dz_2–dz_5 без учебной цели.

## Пересмотр

При объединении в один продукт: выбрать один стек (FastAPI или Express), добавить PostgreSQL, единый `docker-compose.yml`.
